YetAnotherStuffApp for Windows - quick setup
============================================

1. Install Python 3 (once)
   - Microsoft Store: search "Python 3.12" (or newer) and click Get, or
   - https://www.python.org/downloads/windows/ : run the installer and tick
     "Add python.exe to PATH" on the first screen.
   Nothing else is needed (the app uses only the Python standard library).

2. Unzip the app
   Right-click the zip > Extract All... and choose a folder you own, e.g.
   Documents\YetAnotherStuffApp (not "Program Files": the app keeps its
   data next to itself unless you choose another data folder).

3. Start it
   Double-click "Start Stuff App.bat".
   (Or open a terminal in the folder and type:  py main.py)
   If Windows SmartScreen asks, click "More info" > "Run anyway".
   Tip: right-click the .bat > Send to > Desktop (create shortcut).

4. Use it
   The app opens a desktop window (Tkinter). Start with Help > User guide,
   or New box, then New item. The window title and Help > About show the
   version. Close the window or choose File > Exit to quit.
   For text menus, open a terminal in the app folder and run:
       "Start Stuff App.bat" --console
   Type a choice number and press Enter (0 = back/exit). If Tkinter or a
   graphical display is unavailable, text menus are used automatically.
   To display the version without opening data: py -3 main.py --version
   - Your data is in the StuffData folder next to the app. To keep it in
     another folder, use Tools > Settings (console: Settings: data folder),
     or start with:
         py main.py --data "%USERPROFILE%\OneDrive\StuffData"
   - Exports (PDF / Markdown) open with your default viewer.
   - To import an item text file or photos, put them in the app folder
     (they are listed) or type their full path.
   - Optional: "py -m pip install pillow" lets the app import PNG photos
     (without it, JPEG photos only).

5. Update
   Close the app. Make an independent copy of the complete StuffData folder
   and stuffapp_settings.json, then replace only app code from the ZIP.
   The ZIP contains no inventory or device settings; keep yours in place.
   Test new builds in a separate folder with --data pointing to an empty
   test folder. Do not merge inventories by copying over each other.

6. Open or copy a data folder (same actions as Pythonista and console)
   Tools > Settings offers Browse for an inventory folder..., Enter an
   inventory folder path..., Use default folder (StuffData), How to move
   your inventory..., and Reset current data folder. The current path is
   shown in Settings. Select the data folder itself: StuffData is not appended.
   Every location selector then offers:
   - Open this folder: use its existing inventory (empty if empty).
   - Copy complete folder here: copy ALL files, including photos, types,
     backups, trash, exports and extra files; verify, then use the copy.
     Destination must be completely empty and separate from the source.
     Your original is kept; no inventories are merged or overwritten.
   - Cancel: keep the current location.
   A missing default folder is created only after confirmation. Browse and
   path entry require an existing folder. Console uses a text browser:
   Use this folder selects the displayed path, Parent folder goes up,
   directory names open subfolders, and 0 cancels. Use path entry for another
   drive or an unavailable starting folder.
   Do not edit either folder while copying. Enough free space is needed for
   temporary and final copies. Links/special files are refused. A failed copy
   may leave a partial copy at the reported destination: inspect before retrying.
   If verification succeeded but activation failed, keep both folders; the
   error identifies the completed copy. Restart and check your new path,
   boxes, items and photos before considering removal of the original.
   Settings never makes a partial inventory-only copy. Ordinary backup ZIPs
   are partial: they exclude trash, exports and .tmp/.bak files; latest 15 kept.
   Before every reset/restore, a verified Full recovery (protected) ZIP saves
   all files/empty folders in boxes/items/images/meta/trash/exports. Protected
   ZIPs are never automatically pruned. Existing backups and unrelated files
   remain in place. Ordinary ZIP restores keep trash/exports; full recovery
   restores replace all six folders. Older ZIPs remain readable.
   After an interrupted reset/restore, recovery runs before opening data.
   If blocked, keep all recovery files, restore permissions/free space and
   retry. Never delete journals/staging to bypass the check. If necessary,
   keep the original untouched and restore its protected ZIP into a separate
   empty inventory. Keep other devices/apps closed during these operations.
   Help > Trash, backups and recovery explains archive limits and scope.

This ZIP requires Python. It is not a standalone .exe. Test packages are
not approved releases. BUILD-INFO.json identifies the version, Step 03,
base commit and SHA-256 file inventory (including uncommitted app changes).
iCloud folder recognition on iPhone does not establish synchronization
with Windows. Avoid simultaneous edits on multiple devices.

BOX ORDER (0.3.8)

Windows: Sort... above Boxes, or Box > Sort boxes... .
Pythonista: Home > Sort boxes. Console: Boxes > Sort boxes... .
Choose item count (most first is the default), name, created or last modified,
in either direction; Reverse current order flips the current criterion.
Cancel keeps the current choice. Criterion/direction are saved on this device
in stuffapp_settings.json, separate from the inventory and its backups.
Keep that settings file when updating. Box pickers use the same preference.
Last modified records item/photo edits, deletion, restore and both sides of
moves; creation dates are preserved. Old unrecorded events cannot be rebuilt.
Sorting does not change records or exports. See Help > Boxes for details,
legacy timestamp limits and activity left by an operation that fails.

BOX TAGS AND FILTERS (0.3.10)

Create/Edit Box accepts comma-separated tags (20 per box, 64 characters each).
Spaces and case-insensitive duplicates are normalized, preserving spelling.
Tags stay with box data in backups, trash restore and box/inventory exports
(Markdown/PDF). Standalone item exports retain their existing fields/box label.
Filter shows all criteria together. Apply validates and commits the draft;
Clear / Reset filters clears the draft, then Apply activates it. Cancel/Esc
discards edits. Box tag combines with text, box, type, location, origin, prices
and photos. All tags clears only the tag; All boxes clears only the box.
Tag filtering also narrows the box list and works with every box sort mode.
Tag choices offer A-Z/Z-A, most/fewest boxes and Reverse tag order. The order
is saved on this device on Apply; active filters last only for the session.

Filtered boxes use amber; filtered items use teal. Each list shows FILTERED,
visible/total counts and the criteria affecting that list, even with no matches.
Sorting alone keeps the normal appearance. Clear filters beside Filter resets
the active search and all filter conditions immediately (Search > Clear filters),
without opening the form. Clear box tag removes only the tag restriction.
Move opens a destination-box dropdown with Move and Cancel. All other boxes
are available, including destinations hidden by the current tag filter.
Use a test inventory for the visual checklist, including Enter/Esc and focus.
