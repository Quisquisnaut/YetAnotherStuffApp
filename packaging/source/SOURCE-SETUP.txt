YetAnotherStuffApp - portable source/console test package (Step 03)

Extract the complete ZIP and keep main.py next to stuffapp.
Requires Python 3. No third-party dependencies are required.

Console: python3 main.py --console
Desktop: python3 main.py (Tkinter GUI if available, otherwise text menus)
Version: python3 main.py --version
Test data: python3 main.py --console --data /path/to/empty/test-inventory

On Windows use py -3 instead of python3. On Android use the Python command
provided by your interpreter (e.g. python in Termux).
For iPhone/iPad use the Pythonista package and its dedicated instructions.

By default StuffData is next to main.py. --data overrides STUFFAPP_DATA,
which overrides the location saved in Settings. Keep independent backups
before changing a data location or updating. This package contains no data.
BUILD-INFO.json records the version, Step 03, base commit and file hashes.

Settings has Browse for an inventory folder..., Enter an inventory folder
path..., Use default folder (StuffData), How to move your inventory... and
Reset current data folder, consistent with Windows GUI and Pythonista.
Console Browse uses text menus: Use this folder, Parent folder, subfolders;
0 cancels. Use path entry for another drive or unavailable starting folder.
Every selector offers Open this folder / Copy complete folder here / Cancel.
Copy includes ALL files (also backups, trash, exports and extra files),
requires a completely empty separate destination, verifies contents, then
selects the copy. The original is kept. Missing default folders are created
only after confirmation; Browse and path entry require existing folders.
On failure inspect the reported destination for a possible partial copy.
A verified copy is kept if activation fails. Ordinary backup ZIPs are partial:
they exclude trash, exports and .tmp/.bak files; latest 15 ordinary ZIPs kept.
Before reset/restore a verified Full recovery (protected) ZIP saves all files
and empty folders in boxes/items/images/meta/trash/exports. Protected ZIPs are
never automatically pruned. Existing backups and unrelated files stay in place.
Ordinary ZIP restoration keeps current trash/exports; full recovery replaces
all six folders. Older ZIPs remain readable. Interrupted reset/restore recovers
before opening the inventory. If blocked, preserve recovery files and restore
access/free space before retrying; never bypass by deleting journals/staging.
Read Help > Trash, backups and recovery for scope, limits and safe recovery.

BOX ORDER (0.3.8)

Windows: Sort... above Boxes, or Box > Sort boxes... .
Pythonista: Home > Sort boxes. Console: Boxes > Sort boxes... .
Choose item count (most first is the default), name, created or last modified,
in either direction; Reverse current order flips the current criterion.
Cancel keeps the current choice. Criterion/direction are saved on this device
in stuffapp_settings.json, separate from the inventory and its backups.
Keep that settings file when updating. Box pickers use the same preference.
Last modified records item/photo edits, deletion, restore and both sides of
moves; creation dates are preserved. Old unrecorded events cannot be rebuilt.
Sorting does not change records or exports. See Help > Boxes for details,
legacy timestamp limits and activity left by an operation that fails.

BOX TAGS AND FILTERS (0.3.10)

Create/Edit Box accepts comma-separated tags (20 per box, 64 characters each).
Spaces and case-insensitive duplicates are normalized, preserving spelling.
Boxes > Filter boxes... or Search opens a compact overview of all criteria.
Edit only the fields needed, then Apply. Clear resets the draft, not the live
filters; Apply activates the reset. Cancel/Back discards the draft. Box tag
combines with text, box, type, location, origin, prices and photos, and narrows
the box list without changing the chosen box order. All tags clears only tag;
All boxes clears only the specific box. Tag choices have counts, A-Z/Z-A,
most/fewest boxes and Reverse tag order. Tag order saves on this device on
Apply; active filters last for the session. Tags survive restart, backups,
trash restore and box/inventory Markdown/PDF exports. Standalone item exports
retain their existing fields and box label.

Box and item lists show FILTERED, visible/total counts and active criteria,
including zero matches. Amber/cyan ANSI headings distinguish filtered boxes
and items where supported; plain terminals and NO_COLOR keep the text labels.
Sorting alone is not filtering. Search > Clear filters clears active filters
immediately, without editing a form. Boxes > Clear box tag removes only the tag.
Box contents always shows every item in that box independently of Search.
